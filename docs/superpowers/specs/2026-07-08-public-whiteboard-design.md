# 公共展示板设计文档

> 日期：2026-07-08
> 状态：待审核

## 概述

一个公共实时协作展示板网站，允许所有用户在同一块无限画布上使用画笔绘画、张贴图片、橡皮擦除。用户打开网页输入昵称即可加入，系统分配颜色标识身份。实时同步所有操作，支持桌面、平板、手机三端。视觉采用手绘纸感涂鸦风格。

## 需求摘要

### 核心功能
- **自由绘画**：画笔工具，可从色板中任意选择颜色（HTML color picker）、粗细（细/中/粗三档）
- **张贴图片**：上传图片，拖拽放置到画布，可缩放
- **橡皮擦**：点击删除整条笔画（命中检测，非像素擦除）
- **用户标识**：实时显示所有在线用户的光标位置 + 昵称标签（用其分配的颜色）
- **导出/保存**：将整块展示板导出为 PNG 图片
- **撤销**：撤销自己最近一笔

### 非功能需求
- **实时同步**：所有用户操作即时同步，体验流畅
- **无限画布**：可自由平移和缩放，画布无边界限制
- **多端适配**：桌面（鼠标）、平板（触控笔/手指）、手机（手指）
- **手绘纸感**：米黄纸张背景 + 粗黑描边 + 硬阴影涂鸦风格
- **用户身份**：输入昵称加入，系统随机分配颜色

## 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 实时通信 | PartyKit (Cloudflare Workers) | 性价比最高（$5-20/月），专为实时协作设计，边缘部署低延迟 |
| 数据同步 | Yjs (CRDT) | 原生解决多人同时绘画的冲突问题，支持离线合并 |
| 前端渲染 | Canvas 2D + 原生 JS | 完全掌控纸感风格和交互，轻量无框架包袱 |
| 手绘效果 | rough.js (轻量库) | 生成粗糙手绘笔触，匹配涂鸦审美 |

### 成本预估
- PartyKit 运行于 Cloudflare Workers Paid 计划：$5/月起
- Durable Objects 按量计费（请求 + 存储）
- 大多数实时应用总成本：$5-20/月，符合预算（≤$20/月）

### 组件设计

#### 1. 昵称入口模块 (`main.js`)
- 启动时全屏遮罩弹窗，输入昵称后进入画板
- 系统从预设调色板随机分配一个颜色（红/蓝/绿/橙/紫/青等高对比色）
- 昵称和颜色绑定为本用户会话身份
- 空昵称禁止进入，输入框红色边框提示

#### 2. Canvas 渲染引擎 (`canvas-engine.js`)
- **双层 Canvas**：
  - 主画布：渲染笔画和图片
  - 光标层：独立绘制实时用户光标，避免重绘主画布的开销
- **视口变换**：维护 `offsetX/offsetY`（平移）和 `scale`（缩放），实现无限画布
  - 世界坐标 ↔ 屏幕坐标转换函数
  - 所有数据存储世界坐标，渲染时转换为屏幕坐标
- **渲染循环**：监听 Yjs 数据变化触发重绘，按插入顺序（z-order）依次绘制图片和笔画
- **纸感效果**：rough.js 生成粗糙手绘笔触；笔画使用 `lineJoin:round` + 微抖动模拟手绘
- **视口裁剪**：跳过渲染视口外的内容，提升性能

#### 3. 工具栏 (`toolbar.js`)
- **画笔**：颜色（HTML color picker 任意选择）、粗细（细2px/中4px/粗8px三档）
- **橡皮**：点击删除整条笔画（命中检测：点到笔画线段距离 < 笔画宽度的 1.5 倍 + 8px 基础容差）
- **图片**：点击触发文件选择，上传后拖拽放置到画布，支持缩放
- **导出**：将当前视口或全部内容导出为 PNG
- **撤销**：撤销自己最近一笔（从 Yjs Array 移除）
- **响应式形态**：
  - 桌面端：左侧或顶部固定工具栏
  - 平板端：底部浮动工具栏
  - 手机端：底部精简工具栏（可折叠展开）

#### 4. 视口控制器（集成于 `canvas-engine.js`）
- 桌面端：鼠标滚轮缩放（以光标为中心）；空格+拖拽 或 中键拖拽 平移
- 移动端：双指捏合缩放；双指拖动平移
- 迷你导航地图（右下角）：显示全局内容范围和当前视口位置

#### 5. 实时用户系统 (`cursor-layer.js` + `yjs-sync.js`)
- 光标层实时显示所有在线用户的光标位置 + 昵称标签（用其分配的颜色）
- 顶部状态栏显示在线人数和用户头像列表
- 用户离开时自动清除其光标（awareness 自动清理）
- 移动端光标层降低更新频率（60fps → 30fps）以节省性能

#### 6. Yjs 同步层 (`yjs-sync.js`)
- 管理 Y.Doc 生命周期和 PartyKit 连接
- 监听共享数据变化，触发渲染引擎重绘
- awareness 管理光标位置和用户信息
- 连接状态管理（连接中/已连接/重连中/断开）

#### 7. 导出模块 (`export.js`)
- 临时调整视口包含全部内容范围
- Canvas.toDataURL 生成 PNG
- 触发浏览器下载

### 数据结构

Yjs 共享文档结构：

```javascript
Y.Doc
├── strokes: Y.Array<Y.Map>   // 笔画集合
│   每条: { points: [[x,y],...], color: "#422006", width: 4, userId: "abc" }
├── images: Y.Array<Y.Map>    // 图片集合
│   每张: { x, y, w, h, dataUrl, userId }
└── awareness                 // 临时状态（不持久化）
    每用户: { cursor: {x,y}, name: "Alex", color: "#ef4444" }
```

- 笔画存储为世界坐标点数组，支持无限画布
- 图片以 dataURL 存储：
  - 小图直接存
  - 大图自动压缩到 1080px 宽度 + JPEG 0.8 质量
  - 超过 5MB 拒绝并提示用户
- awareness 存光标位置等临时数据，不持久化，用户离开自动清除

### 数据流

1. **绘画**：用户按下→移动→抬起
   - 按下：开始记录点
   - 移动：本地实时绘制预览（乐观更新），收集点
   - 抬起：整条笔画插入 `strokes` Y.Array → Yjs 同步到所有人 → 各端重绘

2. **橡皮擦除**：单指/鼠标点击 → 命中检测找到笔画 → 从 Y.Array 删除 → 同步给所有人

3. **图片张贴**：File 读取 → 压缩 → 插入 `images` Y.Array → 所有人收到 dataURL 后渲染 → 单指拖动定位

4. **光标移动**：鼠标/手指移动 → 写入 awareness → PartyKit 广播 → 其他人光标层更新

5. **用户加入**：输入昵称 → 连接 PartyKit → 加载历史 Yjs 文档 → 渲染已有内容 → 写入 awareness（昵称+颜色+光标）

6. **导出**：计算所有内容的边界范围 → 临时调整视口包含全部 → Canvas.toDataURL → 下载 PNG

## 多端适配

### 响应式布局
- 画布全屏自适应（`width: 100vw; height: 100vh`）
- 工具栏根据屏幕宽度切换形态：
  - `≥1024px`：桌面端布局
  - `768-1023px`：平板端布局
  - `<768px`：手机端布局

### 触摸交互

| 操作 | 桌面端 | 移动端 |
|------|--------|--------|
| 绘画 | 鼠标按下拖动 | 单指拖动 |
| 平移画布 | 空格+拖拽 / 中键拖拽 | 双指拖动 |
| 缩放 | 滚轮（以光标为中心） | 双指捏合 |
| 橡皮擦除 | 点击笔画 | 单指点击笔画 |
| 图片放置 | 拖拽 | 点击上传后单指拖动定位 |

### 关键实现点
- 使用 **Pointer Events** 统一处理鼠标/触摸/触控笔（而非分别监听 mouse/touch 事件）
- 通过 `pointerType` 区分输入类型，触控笔可提高笔触精度
- 双指手势识别：记录两指距离和中心点，计算缩放比例和平移增量
- 工具栏触摸友好：最小触控区域 44×44px，防止误触
- 防止移动端默认行为：`touch-action: none` 避免页面滚动干扰画布

## 错误处理

- **连接断开**：顶部显示"重连中..."横幅，本地操作暂存到队列，重连后通过 Yjs 自动合并同步
- **图片过大**：自动压缩到 1080px 宽度 + JPEG 0.8 质量，超 5MB 拒绝并提示"图片过大，请选择较小的图片"
- **昵称为空**：禁止进入，输入框红色边框 + 提示文字"请输入昵称"
- **性能下降**：移动端自动降低光标更新频率，视口外内容跳过渲染

## 性能优化

- 笔画绘制使用 `requestAnimationFrame` 节流
- 光标层在移动端降低更新频率（60fps → 30fps）
- 图片渲染在低性能设备降级为预览缩略图
- 视口裁剪：只渲染当前可见范围内的笔画和图片
- Yjs 批量操作：单次笔画作为一次 Yjs 事务提交，减少同步开销

## 模块职责边界

每个模块单一职责，通过明确接口通信：

- **`main.js`**：应用入口，协调各模块初始化。依赖：所有模块
- **`canvas-engine.js`**：只负责渲染和视口变换。输入：Yjs 数据 + 视口状态。依赖：rough.js
- **`toolbar.js`**：只负责工具切换和参数设置。输出：当前工具状态。依赖：canvas-engine
- **`cursor-layer.js`**：只负责光标渲染。输入：awareness 数据。无外部依赖
- **`yjs-sync.js`**：只负责数据同步和连接管理。输出：Yjs 文档 + awareness。依赖：yjs, y-partykit
- **`export.js`**：只负责导出。输入：canvas-engine。依赖：canvas-engine

## 不在范围内（YAGNI）

以下功能明确不做，避免过度设计：
- 文字输入工具（用户未要求）
- 形状工具（矩形/圆形/箭头，用户未要求）
- 多房间/多页面（当前是单一公共展示板）
- 用户账号系统（输入昵称即加入，无需登录）
- 权限控制（公共开放，所有人可画）
- 版本历史回溯（Yjs 自动持久化当前状态即可）
- 离线模式（在线实时场景，断线暂存即可）
